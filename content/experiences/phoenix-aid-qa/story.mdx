## QA, Automation, and Regulated Delivery

Phoenix Aid gave me a chance to work in a setting where quality was not a vague goal. It was part of the release process, part of the documentation process, and part of the operational trust teams needed before shipping.

My role blended hands-on QA execution with automation. I built Selenium and C# test coverage across web and API layers, then integrated those checks into GitHub Actions so regressions were caught earlier instead of being discovered after deployment.

I also spent time in the defect loop itself. Logging and triaging 50+ issues forced me to get better at communicating root cause, reproduction steps, and practical severity. That work mattered because it improved release stability and gave engineering a clearer path to fix the right things first.

The compliance side was equally important. Writing SOP-aligned validation documentation taught me how to operate in an environment where evidence, traceability, and consistency matter just as much as the technical fix.
